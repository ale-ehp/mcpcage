# Security policy

## Reporting a vulnerability

Please report vulnerabilities privately through GitHub's "Report a vulnerability" button on the
Security tab of this repository. Do not open a public issue.

Include:

- the mcpcage version and how you run Docker (Docker Desktop, Colima, OrbStack, Linux);
- the server and the command or configuration involved;
- a working reproduction, ideally a small MCP server or script.

Reports without a working reproduction, including reports generated by AI tools that have not been
run, will be closed. This keeps maintainer time for real problems.

## What counts

The most valuable reports show one of these:

- a caged server reading files outside its mounts, reaching the network without `--allow-net`, or
  running as root;
- a change to tool definitions that mcpcage does not block;
- a tool call that reaches the server although the tool is not approved;
- an edit to an audit log that `mcpcage audit verify` does not detect.

[THREAT-MODEL.md](THREAT-MODEL.md) lists what is out of scope, such as container escapes caused by
kernel or Docker vulnerabilities.

## Response

You will get an acknowledgement within a week. Fixes for confirmed issues are released with a
GitHub security advisory that credits the reporter, unless you prefer otherwise.
